# Design Notes

Committed, chronological record of design decisions. Notes explain **why**, not just what. Code and `doc/` remain the source of truth for behavior.

## Naming

`notes/YYYY-MM-DD-<slug>.md` — for example `notes/2026-10-28-lease-state-machine.md`.

## Rules

- Write a note before committing a non-trivial milestone.
- Keep it short (20–60 lines): context, options, decision, tradeoffs, verification, follow-ups.
- Append to an existing note when continuing the same design; create a new note for a new decision.
- Link related notes and specs instead of copying them.
- Notes are committed with the milestone they describe.
